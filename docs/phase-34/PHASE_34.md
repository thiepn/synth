# Phase 34 — PWA, Offline Runtime & Installability Hardening

Status: implemented.

## Purpose

Synth already stores projects and sample assets locally.

Phase 34 makes the application shell itself installable and available offline, so local-first project data is useful even when the network is unavailable.

The phase deliberately separates:

- project data persistence → IndexedDB from Phases 32–33
- app-shell/runtime caching → Service Worker from Phase 34

## Subpath-safe production build

Vite now builds with:

~~~text
base: "./"
~~~

This prevents absolute /assets/... URLs from breaking when Synth is deployed below a repository path such as GitHub Pages.

The same build therefore works from:

- local preview
- domain root
- GitHub Pages repository subpath
- installed standalone PWA

## Build identity

Every production build exposes:

~~~text
__SYNTH_BUILD_ID__
~~~

On GitHub Actions the value derives from GITHUB_SHA.

Local builds use a unique local timestamp identifier.

The build ID is passed to the Service Worker registration URL:

~~~text
sw.js?v=<build-id>
~~~

This provides deterministic update identity for deployed commits without adding Node typings to the browser TypeScript graph.

## Install icons

The build generates:

- 180×180 Apple touch icon
- 192×192 PWA icon
- 512×512 PWA icon

The 512 icon is also declared maskable.

Artwork stays well inside the launcher safe zone, with an opaque background extending to the full icon bounds so circular/squircle launchers do not clip the central waveform.

Raster assets are generated by:

~~~text
scripts/generate-pwa-icons.mjs
~~~

No image-processing dependency is required.

The generator uses Node built-ins only and runs automatically through:

- predev
- prebuild

## Service Worker

The Service Worker lives at:

~~~text
public/sw.js
~~~

and is copied unchanged into the production root.

### Cache version

Each build uses:

~~~text
synth-shell-<build-id>
~~~

### Install

On install:

1. fetch the app root with cache reload
2. cache the root HTML
3. parse same-scope src/href dependencies from the built HTML
4. cache hashed JS/CSS/assets
5. cache manifest and icon resources

Optional resource failure does not make the entire installation fatal.

### Activate

When a new worker activates:

- old synth-shell-* caches are removed
- current clients are claimed

### Navigation strategy

Navigation requests are network-first.

If the network is unavailable:

- exact cached navigation is attempted
- cached app root is used as the final offline shell fallback

### Static asset strategy

Scripts, styles, images, fonts, manifest resources and Vite /assets/ resources use cache-first behavior.

Resources are cached only when:

- request is GET
- URL is inside the Service Worker scope
- response is successful
- response is not opaque

The Service Worker never intercepts cross-origin resources.

## Controlled update lifecycle

A new Service Worker does not force-reload the current app immediately.

When a new worker reaches waiting state:

~~~text
updateAvailable = true
~~~

The user gets an UPDATE control.

Only after explicit activation does Synth send:

~~~text
SKIP_WAITING
~~~

When the new worker becomes controller, the page reloads.

## Project-safe updates

A PWA update can cause a reload, so UPDATE integrates with ProjectStore.

Before applying an update:

1. unresolved project conflicts block update
2. dirty non-conflicted project state is saved
3. if save fails, update is aborted
4. only then is the waiting Service Worker activated

This prevents app updates from discarding unsaved musical work.

## Install UI

The compact header PWA control exposes:

- PWA… while initializing
- INSTALL when beforeinstallprompt is available
- APP when already installed
- OFFLINE when network is unavailable
- UPDATE when a worker update is waiting
- WEB for browser mode

## Manual-install fallback

beforeinstallprompt is not universal.

When automatic install promotion is unavailable, the WEB control opens instructions:

- iPhone / iPad: Share → Add to Home Screen
- Android / desktop: browser menu → Install app / Add to Home screen

The panel also exposes a manual update check.

## Connectivity behavior

Online/offline state is tracked from browser events.

Going offline does not affect:

- project editing
- Pattern playback
- locally stored sample assets
- IndexedDB autosave
- internal renders

Network-only capabilities outside Synth's local runtime are not emulated.

## Installability boundary

Phase 34 implements the app shell/runtime requirements for installability.

It does not assume install UI is identical across browsers.

Synth treats:

- automatic install prompt
- manual Add to Home Screen
- standalone mode detection

as separate browser capabilities.

## Offline data model

Offline operation relies on two independent layers:

~~~text
Service Worker
  app HTML / JS / CSS / icons
          +
IndexedDB
  ProjectDocument / versions / raw sample bytes
~~~

The Service Worker intentionally does not duplicate imported user audio into Cache Storage.

Raw sample bytes remain authoritative in IndexedDB.

## Phase boundary

Phase 34 does not yet implement:

- full accessibility audit
- keyboard/focus hardening across every surface
- reduced-motion/high-contrast adaptations
- low-end runtime benchmarking
- workerization of CPU-heavy analysis/render preparation
- long-session memory soak
- iOS/Android/desktop interaction certification
- full release-candidate fault injection

Those belong to later hardening phases.

## Safety invariants

- Service Worker scope stays inside Synth's deployed app path
- cross-origin requests are not intercepted
- update activation is explicit
- dirty project state is saved before update reload
- unresolved project conflicts block reload-causing updates
- old caches are deleted only when a new worker activates
- app shell caching does not duplicate user sample bytes
- install icons are build-generated deterministically from one safe-zone design
- GitHub Pages deployment uses the same production build command as CI
